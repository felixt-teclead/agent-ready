Why we move from Superpowers to Pocock's skills

Agents now write more PRs than we can review. The new setup catches more problems before a person has to look, and it keeps the team's rules in the repo, where everyone can see and change them.

The idea in one line

From Matt Pocock's talk "Fixing the PR bottleneck": catch each problem in the cheapest layer, so people only review what needs a person.

Automated checksLint, types, tests. They cost CPU time and give the same answer every time.
Automated reviewAn agent in its own context checks the code against our standards. It costs tokens.
Human reviewThe scarcest layer. It should get the few PRs that need judgment.

Five strengths of the new setup

Each card compares what Superpowers does today with what Pocock's skills plus our agent-ready plugin do.

Tests

Tests that only pin behaviour

SuperpowersNo design skill. Agents write tests against a module's internals, and those tests get merged unread. The next agent treats them as rules nobody chose and bends its change around them.

New setupDeep modules and tests only at seams agreed up front. Tests pin what a module does, and the inside stays free to change.

better tests, and no hidden constraints piling up in code nobody reviewed.
Shared knowledge

What one developer learns, every agent knows

SuperpowersThe process lives in each person's plugin, and conventions sit in personal setups.

New setupAGENTS.md, docs/CODING_STANDARDS.md, CONTEXT.md and ADRs live in the repo. A lesson one person writes down reaches every session on the team.

knowledge that spreads through the repo instead of staying with one person.
Decided together

We change the rules together

SuperpowersA plugin update changes how agents work in every repo, and nobody sees a diff.

New setupEvery change to a steering file is a PR, and a human merges it. A hook stops agents from merging those PRs themselves.

rule changes get discussed and reviewed like code.
One standard

Everyone ships against the same standard

SuperpowersThe reviewer checks a generic list from the plugin. Each person adds their own conventions.

New setup/code-review checks every diff against one docs/CODING_STANDARDS.md and the ticket, each in a fresh sub-agent.

every PR is judged by the same rules, whoever or whatever wrote it.
Automation

Shared labels let us automate more

SuperpowersPlan files in the repo. Nothing tells an agent which work it may take on its own.

New setupEvery repo uses the same triage labels. Agents take ready-for-agent tickets with nobody watching; ready-for-human tickets stay with people.

agents pick up work safely on their own, and people keep the work that needs judgment.

What you type, before and after

The path from idea to PR stays familiar. What it leaves behind changes.

Superpowers
brainstorming→writing-plans→subagent-driven-development→finishing-a-development-branch
Leaves a spec file and a plan file in docs/superpowers/.
New setup
/grill-with-docs→/to-spec→/to-tickets→/implement→PR
Leaves CONTEXT.md and ADR updates, a spec issue, ticket issues, and a PR that closes its ticket. /implement works test-first and runs /code-review itself.

The honest part

What Superpowers still does better

  • More written rules against tests that lie, checked at review too. Its writing-good-tests.md is worth copying into our review rules.
  • Not ready to let go? The Stay Stubborn tier keeps its plan-and-execute loop and sends design, specs, tickets and review to Pocock's skills.

What the switch costs

  • Setup: about 99k tokens and 9 minutes. Scan: about 103k tokens and 6.5 minutes. One trial on a repo with 2,333 files.
  • The migration needs a person to approve glossary entries and merge one PR. Its token cost is not measured yet.
  • Pocock's skills for PR bodies and retros are still in beta, so the plugin does not ship them yet.

How to switch

Install the plugin

claude plugin marketplace add \
  felixt-teclead/agent-ready
claude plugin install \
  agent-ready@teclead

Ask where your repo stands

Type /agent-ready:what-to-do. It reads the repo, names one next step and explains the options.

Migrate

/agent-ready:adopt-pocock-methodology switches Superpowers off for the repo, folds old specs and plans into CONTEXT.md, ADRs and issues, and puts it all in one PR that a human merges.
